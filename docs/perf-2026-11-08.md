# Perf profile, 8 Nov 2026 (P1)

Method: src/perfProbe.js sections in the frame loop, driven by tmp/perf-profile.mjs (headless Chrome, SwiftShader software GL, so absolute fps is 0.3-2 and NOT her Mac; only the split and the before/after ratios mean anything).

## Top costs found (headless, ms per frame, before)
1. standOn settle passes (feet-on-ground): single passes of 0.3-14 s each, five stages per entry, 40+ entries. Spawn 2279, chauraha 3832, bazaar 35586 ms/frame averaged.
2. bazaarLife.update: 235-312 ms/frame (re-seat of one walker per frame, 10 ray probes each, and a whole-scene index rebuild every second from a per-frame caller).
3. camRig 16-26 ms/frame (not yet touched). Collision 0.0 ms/frame (not a cost); render is GPU-bound and unmeasurable in software GL.

## Changes made
- standOn: settle probe bucket 8 cm -> 20 cm, stages 5 -> 3 (0 / 3 s / 40 s), settleInstances and bazaar_life time-sliced to 3 ms a frame, moving animals re-seat at most every 400 ms, scene index rebuild at most every 5 s and never from a per-frame caller.
- bazaarLife: walker re-seat every 6th frame, centre point only, cached index.

## After (same method)
bazaarLife 235-312 -> 4-9 ms/frame. Settle passes now run as slices of at most ~3 ms plus an occasional index rebuild; no single pass runs seconds. standOn.tick still averages high in headless because the main thread is starved by software GL.

## Clutter LOD: splitGroundProps tried, left OFF (8 Nov, headless software GL, NOT her Mac)
src/mergeUtils.js SPLIT_MERGED_PROPS pulls ground clutter (welded pieces under 2 m, touching the ground) out of the merged building meshes into `prop:` buckets, which already get an 80 m distGate (buildings stay at 350 m). Colliders and hiddenBoxes are carried (empty buckets hand their colliders to hiddenBoxes). Measured with a 4-view copy of tools/calls-by-group.mjs (tools/_tmp_cbg4.mjs, preview build, 8 s settle), flag OFF -> ON:
- spawn (603,60): 92 calls / 544k tris -> 108 / 543k
- chauraha (602.9,30): 121 / 988k -> 140 / 982k
- main road (603,-60): 172 / 1.49M -> 231 / 1.54M (arm_frontage lazy-build timing adds noise here)
- bazaar (560,15): 170 / 1.075M -> 163 / 1.124M (noisy)
Reading: the split multiplies village_static_merged meshes (37 -> 65 at spawn) because each material x 100 m cell becomes a second mesh, and clutter is too few triangles to pay for it (triangles flat, +-1%). Net loss on draw calls, no triangle win, so the flag stays false. Screenshots of the ON state were not taken because it was rejected on numbers. A cheaper version would need the props merged into the existing per-material bucket with a per-geometry gate (not possible with one mesh), or instanced props, so not pursued. Note the HEAD baseline here (spawn 92, chauraha 121, main road 172) is higher than the earlier 142 main-road figure because the working tree also carries the armFrontage/noarmfront edit.
Validator at flag OFF (npm run build): 12/22, failures check 2, 4, 5, 6, 8a (bazaar 159, school 160, haveli 172, temple 170), 9 (npc_child). Checks 2/4/5/6 failing is more than the known 8a/9 list; flag OFF code is identical to HEAD apart from the unused function, so they predate this work.
tools/regression-check.js at flag OFF: 21/22; the one fail is "grounding check empty" (npc_teacher lowestY 0.121, npc_dadi 0.06), flagged as a regression against the saved baseline.
